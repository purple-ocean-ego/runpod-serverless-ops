# 参照素材 → プロンプト設計スキル

参照画像・参照動画・参照音声（`<Picture N>` / `<Video N>` / `<Audio N>`）を読み込み、R2V 動画生成（MiniMax H3 想定）のプロンプトを **ユーザーと対話しながら** 完成させるためのスキルです。

本スキルは「手順（本ファイル）」と「詳細リファレンス（サイドカーファイル）」に分離しています。詳細なテンプレート・ワークフローは以下のサイドカーファイルを参照してください。

- **[references/prompt-template.md](references/prompt-template.md)** — プロンプトの完全テンプレート（6 セクション構造・空欄版・埋め方・モデル制限時の対応）。
- **[references/workflow-guide.md](references/workflow-guide.md)** — 5 ステップの詳細手順、ヒアリング質問リスト、内容チェック基準、秒割り指針、最終チェックリスト。

---

## 🛡️ ガードレール（最優先）

このスキルで何よりも先に守ること。**どの作業ステップよりも優先**する。

- **参照情報と異なるプロンプトを作成しない**。
   - 素材の内容・構図・動き・雰囲気を尊重する。勝手に脱線・改変・追加で美化しない。
   - 素材に無い要素をプロンプトへ付け加えたり、素材の向きや関係を書き換えたりしない。

---

## 🧭 対話ワークフロー（5 ステップ・骨子）

詳細手順・質問リスト・チェック基準は [`references/workflow-guide.md`](references/workflow-guide.md) を参照。骨子だけ下記。

1. **Step 1 - 素材確認**: 素材パスと各参照の役割をユーザーにヒアリングし、マッピングを確定する。
2. **Step 2 - 内容チェック**: 素材を実際に読み、構図・カメラ・向きをメモ。
3. **Step 3 - 秒割り提案**: モーションの変化点で骨切りし、ショットごとにタイムコードを提示。ユーザー承認を得る。
4. **Step 4 - カスタマイズヒアリング**: キャラ・動き・音声・トーンをヒアリングし、素材を損なわず反映する。
5. **Step 5 - プロンプト反映**: テンプレートに対話結果を反映し、素材との整合を最終チェックして提示する。

---

## 🔗 参照素材のマッピング規則

プロンプト内では必ず `<Picture N>` / `<Video N>` / `<Audio N>` の**タグ**を使う。**数値 N は実際の接続順（アップロード順）と必ず一致**させる。ノード側の入力名（`ref_image_N` 等）は接続順に自動対応するため、プロンプトではタグに統一する。

| タグ | 担う役割（例） |
|------|----------------|
| `<Picture 1>` | 全身正面 → 体格・プロポーション |
| `<Picture 2>` | その他の参照画像 → 構図・体の向き・表情基準 |
| `<Picture 3>` | バストアップ → 顔の造形 |
| `<Video 1>` | モーション動画 → 動き・カメラワーク・リズム |
| `<Audio 1>` | 音声トラック → 音・呼吸・環境音・BGM |

- `subject_definitions` の書き方は「◯◯（造形）は `<Picture N>` から、◯◯（動き）は `<Video N>` から」と**ソースを明記**する。
- キャラ外見は複数画像にわたることが多い。その場合は「face/hair from `<Picture 3>`, body/posture from `<Picture 1>`-`<Picture 2>`」のように列挙する。

---

## ✅ すべきこと / ❌ してはいけないこと

**すべき**
- 素材を実際に読み、内容を把握してから書く。
- 各素材の役割をユーザーに確認してマッピングを確定する。
- 秒割りを提案し、ユーザー承認を得る。

**してはいけない**
- 素材に無い要素・構図・動きを勝手に加える。
- 素材の向きや人物関係、内容を都合よく書き換える。

## 🛠️ H3 R2V ワークフロー設定の知見（実測）

「実写の参照動画 ＋ アニメキャラ参照画像」を置換する場合、プロンプトだけではアニメ化が不十分になりやすい。
ワークフロー側のこの3点が大きく影響する（検証済み）。

- **`ref_image_size`**: `match` だと参照画像が生成解像度に縮小され、アニメのアイデンティティが弱まり実写の被写体が混入しやすい。**`max`**（最大2048px短辺を保持）にするとアイデンティティ固定に有効。速度と引き換え。
- **サンプラー**: `reference-heavy` プロンプトは `simple` よりも **`normal` / `beta`** が優れる。`res_multistep` と組み合わせると良好な結果になる。
- **解像度**: 0.4MP ではアニメ細部（髪・瞳）が潰れやすいため、できるなら **0.8MP 以上が望ましい**。ただし VRAM 制約で 0.4MP が限界の環境もある。その場合は `ref_image_size = max` とサンプラー変更で参照の重みを補う。
